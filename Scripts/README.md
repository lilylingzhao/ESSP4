### `0_mkTelluricMask.py`
Generate a mask of wavelengths where there is telluric contamination using both SELENITE models from EXPRES and a TAPAS model for NEID (shared by Eric, generated by Cullen).  This only needs to be run once to generate a telluric mask file to be used when injecting planets.

### `1_mkDataSet.py`
Generates standard spectra and associated files for one data set at a time.  The data set number is specified as one of the require arguments.  It has to be an integer, because this name is used to seed the random number generator.

There are arguments that control how to select observations from each instrument for each day as well as how to separate out a validation set.  To inject planets, specify a file that contains planet parameters.

The script selects spectra for the data set and rewrites them in standardized format.  These spectra are also optionally shifted.  A `DS#.csv` file is produced that contains details about the resultant data set, including the original file names for each observation.


### `1a_mergeSpec.py`
Merge standardized spectra so that all orders are stitched together.  A separate file is saved for each observation.

The script runs data set by data set.  If no data sets specified, all data set with a `DS#.csv` file generated by `1_mkDataSet.py` are run.

The only other argument is whether or not to overwrite existing files.  This script is usually called with the `--overwrite` tag.

The code progresses through each data set by querying for standard spectra files in both the training and validation folders.  The relevant CCF file name is generated from the standard spectrum file name by simply swaping `_spec_` for `_mrge_`.


### `2_runCCFs.py`
Calculate CCFs for all standardized spectrum file.  A separate file is saved for each observation.

The script runs data set by data set.  If no data sets specified, all data set with a `DS#.csv` file generated by `1_mkDataSet.py` are run.

While the default is to run the EXPRES pipeline, the code is typically called with the `--iccf` tag, which is the code used to generate all ESSP IV CCF files.  Other arguments control various propreties about calculating the CCF and fitting the resultant CCF.

The code progresses through each data set by querying for standard spectra files in both the training and validation folders.  The relevant CCF file name is generated from the standard spectrum file name by simply swaping `_spec_` for `_ccfs_`.


### `3_fitIndicators.py`
Calculate activity indicators and generate a CSV file that collects them all along with information about each observation and its RV.  Separate files are saved for the training and validation subsets.

The script runs data set by data set.  If no data sets specified, all data set with a `DS#.csv` file generated by `1_mkDataSet.py` are run.

The only other argument is whether or not to overwrite existing files.  This script is usually called with the `--overwrite` tag.

The code progresses through each data set using the `"Standard File Name"` column of each data set's `DS#.csv` file.  The relevant CCF files are generated from the standard spectrum file name.


# Post-Processing/Analysis Focused
Scripts relevant to post-processing and analysis of results start with letters (though there's no real reason in this case for them to be ordered)

### A - SDO Data
It's faster to download the needed SDO files separately to them being processed.  This also simplifies parallelizing the processing.  I would set the SDO download going, wait for a few days to download (depending on how many threads to be used in the processing), and then start the processing script going.

It slightly complicates what happens if there are errors or interuptions to a day.  There is therefore also a script that targets time stamps for which there are not saved values.  This is helpful to run after an initial download/processing of all days.

| Script Name          | Description |
| -------------------- | ----------- |
| `Aa_sdoDownload.py`  | Download all relevant SDO files a day at a time|
| `Ab_sdoProcessing.py`| Process all SDO files a day at a time|
| `Ac_sdoTouchUp.py`   | Check each day for time stamps without processed data and attempt to redownload/reprocess|
